# 前端样式说明

这份文档给后续接手前端 UI 的人使用。当前前端已经重构为“简约工作台”风格：扁平、克制、留白明确，适合聊天、知识库和后台管理这种需要长期盯屏操作的产品界面。

## 设计定位

项目不是营销页，也不是炫技型 AI 官网。第一屏必须是可用的登录、聊天或后台操作界面。

- 整体气质：轻量、安静、工程感、文档式。
- 页面结构：左侧导航 / 中央工作区 / 底部输入或表格操作。
- 视觉重点：信息层级、输入效率、表格扫描、弹窗确认。
- 禁止回退到蜂窝发光背景、玻璃拟态、大面积渐变、厚重阴影、紫蓝赛博风。
- 常规容器圆角以 `14px` 为基准，composer、弹窗、悬浮索引卡可以放到 `24px` 到 `28px`；不要回到尖锐方框。

## UI 修改流程

以后每次修改 UI，都必须同时使用这两个技能检查：

```text
$gpt-taste
$minimalist-ui
```

规则：

- 先用 `$gpt-taste` 做交互、按钮对比度、布局密度和动效检查。
- 再用 `$minimalist-ui` 做扁平、白底、浅边框、少阴影和灰色层级检查。
- 如果只是修一个微交互，也要确认没有被通用按钮规则误伤。
- 修改后把新形成的可复用规则补进这份文档。

## 字体

用户要求的字体应写作 `Cascadia Mono`，不是 `casdia mono`。

全局字体保持：

```css
font-family: "Cascadia Mono", "Microsoft YaHei", Consolas, monospace;
```

规则：

- 不引入 Inter、Roboto、Open Sans。
- 不使用 viewport width 控制字体大小。
- `letter-spacing` 保持 `0`，不做负字距。
- 中文正文优先可读性；数字、ID、模型名保留 mono 的工程感。
- 页面标题不宜过大，后台和聊天界面不是 hero 站点。

## 色彩系统

主色固定为 `#4C4F69`。后续不要新增模块主色。

```text
主色: #4C4F69
主色 hover: #3f4157
正文: #202123
弱文本: rgba(48, 52, 70, 0.58)
页面底色: #F7F6F3
工作区底色: #FBFBFA
卡片 / 面板: #FFFFFF
弱面板: #F9F9F8
边框: #EAEAEA
危险色: #7f1d1d
危险底: #FDEBEC
成功色: #346538
成功底: #EDF3EC
警告色: #956400
警告底: #FBF3DB
信息色: #1F6C9F
信息底: #E1F3FE
```

规则：

- 大面积区域只用浅暖灰和白色。
- 主色只用于主按钮、发送箭头、当前导航、Think 开启态和关键选中态。
- 状态色只用于状态胶囊、错误提示和确认弹窗，不扩散成模块主题。
- 背景不使用彩色渐变；需要层次时用边框、留白和极轻阴影。

## 布局

### 登录页

- 登录卡片居中，白底、`1px` 边框、`14px` 到 `24px` 圆角。
- 不展示营销 hero，不增加说明性大段文案。
- 登录 / 注册切换是分段控制，激活态使用主色。

### 会话页

- `.app-shell` 是主结构，左侧导航展开宽度约 `292px`，折叠后 `64px`。
- 聊天工作区使用 `#FBFBFA`，顶部栏和底部 composer 使用白底。
- 新会话欢迎语保留，但不能做成营销页标题。
- 用户消息使用 `#4C4F69` 主色气泡包裹，白字、右对齐；助手消息不需要气泡，直接平铺在背景上。
- 用户和助手消息之间不加横向分割线，靠留白区分上下文。
- 消息行宽度必须和 composer 一致，统一使用 `--chat-content-width`，不能出现消息比输入框窄一截或宽一截。
- Composer 保持底部输入效率，整体是圆润悬浮输入条；按钮和模型选择都必须清晰可点。
- 发送按钮使用圆形上箭头图标，发送中再显示“中断”文字。
- Composer 下方固定显示小字：`AI 也可能会犯错。请核查重要信息。`
- Composer 是悬浮控制条，不占用聊天滚动布局行；不要在底部额外铺一块白色幕布。
- 消息列表必须预留 composer 的底部安全区，避免最后一条消息被悬浮输入框遮住或截断。
- 会话进度 rail 按视口高度延伸，从顶部内容区到 composer 上方，不使用固定 `300px` 的短轨道。
- 会话进度 rail 靠右显示为可轻微倾斜的用户消息刻度，不显示贯穿整栏的竖线；用户对话几次就显示几条，不做窗口裁剪。刻度要紧凑，横线比 ChatGPT 参考图略宽但不能松散。
- 会话进度弹窗只展示用户消息，不展示 AI 输出，也不显示 token。
- 会话进度弹窗必须适配项目滚动条样式；只允许纵向滚动，禁止横向滚动条和原生上下左右箭头。滚动条要嵌在弹窗右侧内边距里，不能越过圆角边界。
- 弹窗与消息刻度之间要有外层 hover 重叠区和短延迟关闭，避免鼠标从刻度移动到弹窗时弹窗消失；不要在弹窗滚动容器本身放会制造横向溢出的外伸伪元素。
- Markdown 代码块使用浅灰卡片样式，复制按钮使用叠方块图标 + “复制”，不要使用主色深底，避免和用户气泡撞色。
- 用户主色气泡内如果出现强调、链接、行内代码等本来使用主题色的元素，必须改为白色或白色透明底，保证可读。
- 历史会话列表使用 ChatGPT 式简洁列表：只显示标题，hover / active 用浅灰底，不显示时间副文本。
- Composer 聚焦时只允许外层输入容器显示焦点反馈，内部 `textarea` 不再画单独 outline 或灰色方框。
- Think 未开启时必须是白底、浅边框、深灰文字；小字使用 `rgba(48, 52, 70, 0.58)`。
- Think 开启后才使用 `#4C4F69` 背景和白字。
- 模型下拉列表里只有当前选中项和 hover 项使用主色，其他模型项保持白底；模型 ID 小字不能压暗到不可读。

### 后台页

- `.admin-page` 使用左侧导航 + 主内容滚动区。
- 后台背景是 `#F7F6F3`，表格和指标卡是白色面板。
- Dashboard 指标使用扁平 bento 网格，不留空洞装饰格。
- 表格以可扫描为第一优先级，避免不必要横向滚动。
- 页面内只保留一个主标题区，不重复堆标题。

## 组件规则

### 按钮

- 主按钮：`#4C4F69` 背景，白字。
- 次按钮：白底、浅边框、深灰蓝文字。
- hover 可以轻微上移 `translateY(-1px)`，但不加厚重阴影。
- active 可以轻微缩放或压下。
- 禁用态：浅灰底、弱文字、无阴影、`cursor: not-allowed`。
- 删除按钮默认红字白底，hover 变红底白字。

### 卡片和面板

```css
border: 1px solid #EAEAEA;
border-radius: 14px;
background: #FFFFFF;
box-shadow: 0 1px 2px rgba(76, 79, 105, 0.04);
```

规则：

- 不把卡片套进卡片。
- 不使用玻璃、发光、厚阴影。
- 面板内容靠留白和边框区分层级。

### 表格

- 表头背景：`#F9F9F8`。
- 行 hover：`#F8F7F4`。
- 操作列居中，按钮高度稳定。
- 文本可省略，但只有实际溢出时才显示 tooltip。
- 状态胶囊使用语义色，不改变整行背景。

### 弹窗

- 遮罩允许轻微 blur。
- 弹窗白底、浅边框、`24px` 左右圆角。
- 错误显示在弹窗内部。
- 底部操作按钮右对齐。
- 删除确认必须使用项目自定义弹窗，不使用浏览器原生 `confirm`。

### Tooltip

- 折叠导航 tooltip 和表格溢出 tooltip 统一为深色底白字。
- 只在必要场景显示，不要给普通按钮滥加 tooltip。
- tooltip 层级要高，不能被表格或弹窗裁剪。

## 动效

项目现在引入 `gsap`，统一通过 `frontend/src/utils/quietMotion.js` 使用。

规则：

- 动效只做进入 reveal：`opacity + translateY(12px)`，节奏约 `0.52s`。
- 后台滚动区使用 `ScrollTrigger`，但不做 pinned section、横向大片滚动。
- 动效服务于“进入时有秩序”，不能影响表格扫描和输入效率。
- hover / menu / modal 过渡保持 `160ms` 到 `240ms`。
- 不使用会导致布局抖动的动画属性，如 `top`、`left`、`width`、`height`。

## 图标

当前项目继续使用内联 SVG，统一规则：

```css
stroke: currentColor;
stroke-width: 1.9;
stroke-linecap: round;
stroke-linejoin: round;
fill: none;
```

规则：

- 导航项、标题、主要操作按钮优先使用图标 + 文案。
- 图标颜色跟随 `currentColor`。
- 不新增多套图标风格。

## 继续改 UI 的检查清单

- 是否保留了 `#4C4F69` 和 `Cascadia Mono`？
- 是否仍然是产品工作台，而不是营销页？
- 是否没有蜂窝发光、玻璃拟态、大面积渐变、厚阴影？
- 常规容器是否保持约 `14px` 圆角，composer / 弹窗 / 悬浮索引是否保持 `24px` 到 `28px`？
- 会话消息是否平铺在背景上，且消息行宽与 composer 一致？
- 发送按钮是否是圆形箭头，composer 下方是否保留 AI 风险提示小字？
- 右侧定位 rail 是否从内容区延伸到 composer 上方，hover 是否能看到具体消息弹窗？
- 主按钮是否主色底白字，hover 后仍可读？
- 表格是否可扫描，操作列是否稳定？
- 错误是否显示在当前上下文或弹窗内部？
- 删除是否使用自定义确认弹窗？
- tooltip 是否只在折叠导航或真实溢出时出现？
- 动效是否只做轻量 reveal，没有干扰输入和管理操作？
