# 前端样式说明

这份文档给新对话接手前端 UI 用。项目的 UI 已经形成自己的风格，后续不要随手套别的后台模板，也不要把导航栏和页面风格改成参考图本身。

## 总体气质

项目当前是“轻量、克制、带一点工程感”的 AI 工具界面。

- 基础色调是浅灰背景、白色面板、深灰蓝主色。
- 不做大面积彩色渐变。
- 不做营销页式 hero。
- 不做过圆的卡片，常规圆角保持 `8px` 左右。
- 按钮和表格强调清晰、可扫描、可反复操作。
- 后台管理也要保持本项目的个人风格，不照搬外部截图的深色侧边栏或紫色大面积设计。

## 字体

全局字体在 `:root` 和 `body` 中定义：

```css
font-family: "Cascadia Mono", "Microsoft YaHei", Consolas, monospace;
```

后台 `.kc-page` 使用：

```css
font-family: "Microsoft YaHei", "Cascadia Mono", Consolas, sans-serif;
```

规则：

- 中文界面优先保证可读性，后台标题可以更稳重，正文不要过粗。
- 表格中的数字、ID、模型名允许保留 mono 气质。
- 不要使用负 letter-spacing。
- 不要用 viewport width 控制字体大小。

## 颜色

主要颜色：

```text
页面背景: #f3f4f7 / #eff1f5 / #f7f7f8
主文本: #202123 / #303446 / #111827
弱文本: rgba(48, 52, 70, 0.58) / #718096 / #64748b
主按钮: #4c4f69
主按钮 hover: #3f4157
边框: #dfe5ef / rgba(76, 79, 105, 0.14)
成功状态: #047857 on #dcfce7
危险操作: #7f1d1d
错误背景: #fee2e2
```

规则：

- 后台知识库、文档、分块页面统一使用灰色体系，不额外引入绿色、蓝色、紫色做模块主色。
- 状态色只用于状态胶囊和错误提示，不要扩散到大面积背景。
- 删除按钮默认只用暗红文字或图标，hover 时才变成红底白字。
- 主按钮 hover 后文字必须变白，不能出现灰字和深色背景重叠。

## 布局

### 会话页

会话页使用 `.app-shell`：

- 展开侧边栏宽度约 `300px`
- 折叠后是 `64px`
- 折叠动画使用 `360ms cubic-bezier(0.16, 1, 0.3, 1)`
- 折叠 rail 的 tooltip 是黑底白字，小三角，靠右浮出

### 后台页

后台页使用 `.admin-shell` / `.admin-sidebar` / `.admin-main` 和新的 `.kc-*` 知识库样式。

规则：

- 后台导航栏不照搬参考图，保持本项目白底、深灰蓝高亮风格。
- 后台也支持隐藏导航栏，行为和会话界面类似。
- 每个模块只保留一个主标题区：小字分类 + 图标 + 大标题。
- 不要在页面内部再重复一遍同名大标题。
- 页面主要内容用白色面板承载，背景是浅灰。
- 表格不要出现横向滚动条，除非内容真的无法合理排布。

## 按钮

通用后台按钮类：

```text
.kc-ghost-button
.kc-primary-button
.kc-row-actions button
.kc-icon-actions button
.kc-icon-button
.admin-refresh-button
```

按钮规则：

- 圆角 `8px`。
- 默认白底、浅边框、深灰文本。
- hover 时可变成 `#4c4f69` 背景和白字。
- hover 时使用轻微上移：`transform: translateY(-1px)`。
- active 或点击反馈可以轻微缩放。
- 禁用态使用浅灰底、弱文字、无阴影、`cursor: not-allowed`。
- 表格操作按钮尽量带图标和文字，不只放孤立图标。
- 同一行操作按钮要排在一行，并放在“操作”列中间。

删除按钮：

- 默认保持白底红字。
- hover 使用暗红底白字。
- 删除知识库、删除文档、删除分块都使用项目内自定义确认弹窗，不用浏览器原生 `confirm`。

## 图标

当前图标主要是内联 SVG，风格统一：

```css
stroke: currentColor;
stroke-width: 1.9;
stroke-linecap: round;
stroke-linejoin: round;
fill: none;
```

规则：

- 标题前需要加图标。
- 导航项需要图标。
- 按钮尽量图标 + 文案。
- 图标颜色跟随 `currentColor`，不要单独写死一堆颜色。

## 表格

后台知识库表格统一使用 `.kc-table-*`：

```text
.kc-table-card
.kc-table-head
.kc-table-row
.knowledge-grid
.document-grid
.chunk-grid
.kc-row-actions
.kc-status
.kc-tag
```

规则：

- 表头背景是极浅灰。
- 行高要足够点击，常见 `76px` 左右。
- 表格文本允许省略，但只有真的显示不全的字段才出现 tooltip。
- tooltip 不应被表格容器裁剪。
- 状态胶囊要和“状态”表头对齐。
- 操作列要居中，按钮之间间距稳定。
- 不把创建时间、更新时间、大小这类次要信息塞爆主列表，可以放进“详情”弹窗。

文档列表建议列：

```text
文档 / 来源 / 处理模式 / 状态 / 分块数 / 类型 / 操作
```

分块列表建议列：

```text
选择 / 序号 / 内容 / 状态 / 操作
```

字符数、token 数、更新时间放进详情弹窗。

## 状态

文档状态映射：

```text
UPLOADED -> uploaded
PROCESSING -> processing
COMPLETED -> success
FAILED -> failed
```

按钮文案映射：

```text
UPLOADED: 分块
PROCESSING: 处理中...
COMPLETED: 重新分块
FAILED: 分块
```

规则：

- `PROCESSING` 时按钮禁用，并通过轮询刷新文档状态。
- 失败原因显示在对应弹窗内，不要飘到页面外层。
- 上传成功只代表 RustFS 保存成功，不代表已经解析和向量化。

## 弹窗

通用弹窗规则：

- 背景遮罩要有 blur。
- 弹窗白底、圆角、轻阴影。
- 错误信息显示在弹窗内部顶部。
- 右上角关闭按钮使用圆形 icon button。
- 底部操作按钮右对齐。
- 删除确认弹窗使用项目自定义样式。

全局限流错误弹窗：

- gateway 返回 `429 Too Many Requests` 时，由 `GlobalErrorToasts` 在页面中上方统一展示。
- 多个限流错误同时出现时，弹窗水平居中，按触发顺序从上到下排列。
- 单个弹窗左侧只放错误文字，右侧是圆形 `X` 关闭按钮。
- `X` 按钮外围使用圆形进度条，进度条耗尽后弹窗自动消失。
- 用户点击 `X` 时立即关闭当前弹窗，不影响其他弹窗。

上传文档弹窗：

- “选择文件”使用自定义文件选择区域，不用浏览器默认裸 input。
- 本地上传时显示文件名和大小。
- 上传只负责 RustFS 存储，成功后文档状态为 `uploaded`。
- 分块策略只在点击“分块 / 重新分块”时选择。
- 自动策略和不分块不展示 chunkSize、chunkOverlap、maxChunks。
- 只有递归分块展示分块大小、重叠大小、最大块数。

文档详情弹窗：

- 上半部分是基础信息。
- 下半部分是耗时信息。
- 耗时包含文本提取、分块、向量化、其他、总耗时。
- 避免出现总耗时小于某个子耗时的视觉误解。

分块弹窗：

- “查看”只读展示完整文本。
- “修改”允许编辑完整文本。
- 查看和修改的文本框边框、字体、字号要一致。
- 修改后提示“修改分块后请重建向量”。

## 下拉栏

当前后台自定义下拉使用：

```text
.kc-select-menu
.kc-select-trigger
.kc-select-options
```

规则：

- 下拉触发器默认像按钮，hover 后平滑变为主色。
- 展开时箭头旋转。
- 菜单圆角 `8px`，内容填满，不留奇怪边缘。
- 选项 hover 和 active 使用主色背景白字。
- 过渡保持 `160ms` 到 `180ms`，不要突兀。

## Tooltip

项目有两类 tooltip：

1. 导航栏折叠时的 tooltip
2. 表格字段被省略时的 tooltip

规则：

- 不要乱用 tooltip。
- 导航栏只有隐藏或折叠后，鼠标靠近图标才显示 tooltip。
- 表格只有字段实际显示不全时才显示 tooltip。
- tooltip 样式参考导航栏：黑底白字、小三角、短动画。
- tooltip 层级要高，不能被表格面板挡住。

## 动画

项目动画是轻量反馈，不是炫技。

常用节奏：

```text
hover: 160ms 到 180ms ease
布局切换: 360ms cubic-bezier(0.16, 1, 0.3, 1)
弹窗 / 菜单进入: 180ms 到 240ms ease
```

规则：

- 刷新按钮点击时图标旋转或按钮进入 refreshing 状态。
- 按钮 hover 可以轻微上移。
- 下拉菜单打开要平滑。
- 不要给表格行做大幅度移动动画，容易影响扫描。

## 继续改 UI 时的检查清单

- 是否保留了本项目的白底灰蓝风格？
- 是否没有重复标题？
- 按钮 hover 后文字是否清晰可见？
- 操作按钮是否在同一行并居中？
- 删除是否使用自定义弹窗？
- 错误是否显示在当前弹窗内？
- 字段省略时是否只有真的溢出才显示 tooltip？
- tooltip 是否没有被父容器挡住？
- 表格是否避免了不必要的横向滚动条？
- 文档状态和按钮文案是否符合状态流转？
- 修改分块后是否提醒重建向量？
